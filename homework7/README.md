#  系統底層與計算機架構：從自製虛擬 CPU 到進階 IPC 同步機制

##  專案與學習概述
本報告核心在於探討計算機系統「由內到外」的運作軌跡。前半段專注於**計算機組織（Computer Architecture）**，透過 Node.js 實作一台 8 位元虛擬電腦，微觀 CPU 的微步驟運作；後半段則延伸至**作業系統（Operating System）**層級，探討多進程與多執行緒環境下的通訊（IPC）與同步控制機制。

---

##  第一部分：自製 8-Bit 虛擬電腦專案 (js-virtual-cpu)

### 1. 核心邏輯與三大角色分工
這台虛擬電腦在軟體後台由三個核心角色分工合作，模擬真實硬體晶片的運作：

* **記憶體 (Memory)：** 使用配置 256 個格子的櫃子，定址空間為 `0x00` 至 `0xFF`。每個櫃子只能存放一個 8-bit 的數字（0~255），負責同時存放「程式碼（指令）」與「資料」。
* **中央處理器 (CPU)：** 電腦的大腦。內含**程式計數器 (PC)** 用於追蹤當前櫃子索引，以及數個**通用暫存器 (Registers)** 作為大腦的短期記憶，暫存運算中的數值。
* **指令集 (Instruction Set / Opcode)：** 與電腦溝通的機器語言。定義特定的十六進位數字代表特定動作，例如：
    * `0x01` ➡️ `LOAD`（搬移資料至暫存器）
    * `0x02` ➡️ `ADD`（將暫存器數值相加）
    * `0x03` ➡️ `STORE`（將結果寫回記憶體）
    * `0x00` ➡️ `HALT`（停機）

### 2. 電腦運作流程：Fetch-Decode-Execute 循環
當執行程式時，核心會陷入一個無限循環，直到遇見 `HALT`：

1. **擷取 (Fetch)：** CPU 根據 PC 當前的記憶體地址，從櫃子中取出一個位元組的資料，隨後 PC 自動遞增。
2. **解碼 (Decode)：** CPU 透過硬體開關電路（在軟體中表現為 `switch-case`）解析該數字。例如讀到 `0x02` 知道是加法。
3. **執行 (Execute)：** CPU 呼叫 ALU（算術邏輯單元）執行加法，更新暫存器狀態，並為下一個循環做好準備。

##  第二部分：作業系統層級：行程間通訊 (IPC) 與執行緒同步

當我們從「單一 CPU 指令運作」抽離，進入多工處理作業系統時，核心課題就變成了：**多個進程或執行緒如何安全地交換資料與同步？**

### 1. 匿名管道 (Anonymous Pipe)
管道是 Unix 系統最古老的 IPC 機制，本質上是作業系統核心 (Kernel) 記憶體中的一塊 FIFO 緩衝區。

* **系統調用：** `pipe(int fd[2])`
* **運作原理：** 呼叫後會產生兩個檔案描述符（FD），`fd[0]` 固定負責讀取，`fd[1]` 固定負責寫入。
* **血緣限制：** 匿名管道沒有真實檔案路徑，必須依賴 `fork()` 讓子進程繼承 FD 表，進而達成父子或兄弟進程間的單向通訊。

>  **核心地雷（關鍵關閉規則）：**
> 在 `fork()` 之後，父子進程必須各自關閉用不到的一端。若**寫入端 (fd[1])** 沒有在所有進程中被完全關閉，讀取端呼叫 `read()` 時就永遠不會讀到 EOF（傳回 0），進程將會永久卡死（Hang）。

### 2. 進階執行緒同步：條件變數 (Condition Variable)
在多執行緒環境中，當我們需要等待某個複雜條件成立（而非單純的鎖保護）時，使用條件變數可以避免高耗能的 Busy Waiting。

* **原子性三部曲：** 當執行緒呼叫 `pthread_cond_wait(&cond, &mutex)` 時，系統會自動**釋放 Mutex ➡️ 讓執行緒進入睡眠 ➡️ 被喚醒時重新競爭 Mutex**。
* **虛假喚醒防禦：** 由於多核處理器可能引發 Spurious Wakeup（虛假喚醒），醒來時條件不一定真的滿足，因此必須使用 `while` 迴圈而非 `if` 來包裹條件檢查。

##  第三部分：觀念總整理與技術對比

### 1. 機制對比表
| 機制名稱 | 運作層級 | 核心目的 | 關鍵特性 / 常見地雷 |
| :--- | :--- | :--- | :--- |
| **Fetch-Decode-Execute** | 晶片/硬體層級 | 驅動 CPU 處理指令的基本步調 | 靠程式計數器 (PC) 控制串行流程 |
| **Mutex (互斥鎖)** | 執行緒/行程 | 保護臨界區段 (Critical Section) | 忘記解鎖引發死結 (Deadlock) |
| **Anonymous Pipe** | 行程層級 (IPC) | 具有血緣關係行程間的半雙工通訊 | 寫入端沒關全會導致讀取端永久阻塞 |
| **Condition Variable** | 執行緒層級 | 複雜條件下的執行緒通知機制 | 醒來必須重新爭奪鎖，須用 `while` 檢查 |

### 2. 核心 Takeaways
* **硬體與軟體的邊界：** 軟體系統的複雜同步機制（如 Pipe 或 Mutex），底層完全仰賴 CPU 的原子指令（Atomic Instructions，如 Test-and-Set）與 Fetch-Decode-Execute 的硬體週期的支援。
* **資源管理防禦思維：** 不論是設計虛擬 CPU 時防範未知指令（`default` case 停機），還是在 Unix 下操作 FD 必須謹慎 `close()`，**「防禦性編程」**是底層系統開發的核心靈魂。
